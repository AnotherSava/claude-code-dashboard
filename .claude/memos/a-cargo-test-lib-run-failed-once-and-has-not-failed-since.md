# A `cargo test --lib` run failed once and has not failed since, and the failure went unnamed.

Seen 2026-09-11 during `.claude/commit-checks.sh`: `test result: FAILED. 839 passed; 1 failed`, with the name filtered out of the captured output by the grep that was reading the summary line, so which test it was is NOT known. It has not recurred in 14 subsequent runs — 8 sequential, then 6 of the prebuilt test binary run concurrently at `--test-threads=8` to force contention — and every one of those was `840 passed; 0 failed`. WHAT IS WORTH KNOWING: the failing run was the one that happened to overlap a release build and an app launch, so the machine was saturated, which points at a wall-clock-sensitive assertion rather than at the change under test (that change was `auto_resize::set_dark_window_background`, whose macOS arm has no test). Nothing in the suite touches the real app data dir or binds a port — checked — so a collision with the running dashboard is not the explanation; `SystemTime::now` is used across ten modules, which is where to look. WHAT TO DO NEXT TIME RATHER THAN NOW: do not chase it cold. Make the next occurrence legible instead — `commit-checks.sh` should print the failing test's name, which means not piping `cargo test` through a filter that keeps only the summary line, since that is what turned a reproducible-once failure into an anonymous one. A `--test-threads=1` re-run on a loaded machine is the cheapest reproduction attempt if it does return.

SECOND SIGHTING 2026-09-13, and it narrowed things without identifying the test. Same shape: `839 passed; 1 failed` inside `.claude/commit-checks.sh`, then 8 clean bare `cargo test` runs immediately after and a clean gate re-run. Both sightings are now inside the gate script and neither is inside a bare `cargo test`, which is the most useful fact so far — the gate runs `npm run check` and a release-profile build around the tests, so the machine is loaded in a way a bare run is not, which fits a wall-clock-sensitive assertion.

CORRECTION to the recommendation above: `commit-checks.sh` is NOT at fault and does not need changing. It prints the failing test's name perfectly well. Both times the name was destroyed by the filter *I* piped its output through — `grep -E "All CI checks passed|ERROR|test result"` keeps the summary line and drops the `test … FAILED` line right above it. The fix is a habit, not a file: when running the gate, keep `^test .* FAILED` and the `failures:` block in whatever filter is used. Doing that is free and is the only thing standing between the next sighting and an actual name.
