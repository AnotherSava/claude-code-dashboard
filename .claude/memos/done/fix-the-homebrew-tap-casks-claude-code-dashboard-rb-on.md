# Fix the Homebrew tap: Casks/claude-code-dashboard.rb on AnotherSava/homebrew-tap main is…

Fix the Homebrew tap: Casks/claude-code-dashboard.rb on AnotherSava/homebrew-tap main is a 0-byte file (blob e69de29, git's empty blob), so `brew install --cask AnotherSava/tap/claude-code-dashboard` cannot work; docs/pages/install.md names it as the primary macOS route. Broken since tap commit e9fbc3b ("chore: bump claude-code-dashboard to 1.9.1", 2026-08-24T07:24Z), which is +0/-92 on the cask; last good content was 4617 bytes at 747dd4e (the 1.9.0 bump). It has shipped broken through v1.10.0 and v1.11.0. ROOT CAUSE: bump-cask.yml's `Commit the bump` step passes `-f content="$(base64 -w0 "$CASK")"`, and the job had just moved to `runs-on: macos-latest` (line 26) so it could run `brew audit`. BSD base64 has no `-w`; run 32701261306 logs `base64: invalid argument` followed by the BSD usage line. A failing command substitution inside an argument word does not trip `set -euo pipefail`, so `gh api` PUT an empty `content`, got 200, and the job went green. WHY NOTHING REPORTED IT, three independent silences: (1) the job exits 0, and GitHub's Actions notifications fire on failure, so no mail; all four repository_dispatch runs (2026-08-24, 2026-08-28 x2, 2026-09-02) concluded success. (2) `Validate the rewritten cask` is gated `if: env.CHANGED == 'true'`, and CHANGED comes from `git diff --quiet` alone and never reads the cask's version, so an empty file is indistinguishable from a genuine no-op; run 33594205980 logs "cask already at 1.11.0, nothing to do" against a 0-byte file. Skipping looked like passing (feedback_not_run_is_not_pass). (3) The bump commit is pushed with GITHUB_TOKEN, so GitHub's recursion guard suppresses the tap's own Tests workflow; every Tests run in that repo is on a human push and none is on a bump commit, so the cask is never audited after the write. FIX, all in the tap repo: restore the cask body from 747dd4e and set version + sha256 for the release being cut; replace `base64 -w0 "$CASK"` with `base64 -i "$CASK" | tr -d '\n'` (or `openssl base64 -A`), which is runner-agnostic; assert the postcondition after the PUT by re-reading the committed file and failing unless it is non-empty and its `version` line equals $VERSION; and make the no-op branch grep the cask's version rather than trusting a quiet diff. The dashboard side needs no change: notify-tap.yml dispatches correctly and its TAP_DISPATCH_TOKEN worked on 2026-09-02. Verify by actually running `brew install --cask` afterwards, since a green tap run is exactly what failed to mean anything here. FIXED 2026-09-11, EXCEPT THAT LAST STEP. Also fixed a latent one nobody had hit: `sed -i -E` means different things on GNU and BSD and this job runs on macos-latest, so the rewrite now goes through a temp file.
