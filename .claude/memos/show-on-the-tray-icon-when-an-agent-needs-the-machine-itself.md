# Show on the tray icon when an agent needs the machine itself.

New global guideline (`~/.claude/CLAUDE.md`, "Taking Over the Machine"): an agent that has to raise a window, move the pointer, synthesize a keystroke or otherwise drive the GUI must ask immediately before each burst, and the dashboard must make that state visible without reading the transcript. Three states, each legible at tray size: normal; a distinct variant while a request is **pending**, so a user away from the chat can see an agent is waiting on them; and a distinct **animated** variant while the interaction is running, so a machine moving on its own is never ambiguous. Back to normal the moment the burst ends, INCLUDING when it fails or is declined — an icon stuck on "interacting" trains the user to ignore it. SHAPE: a loopback route beside `/api/window` for an agent to declare and clear the state (it is a claim about the caller, so it needs no cross-machine half); the state on `AppState` rather than stamped at emit time, since `tray_badge::refresh` must be able to read it; two render paths alongside the existing `lights`/`number` styles in `tray_badge.rs`, which already composes variants of the app icon and already has an alert overlay to borrow the geometry from; and a tick for the animation, which is the one genuinely new machinery here — every other tray repaint today is edge-driven from `emit_sessions_updated` / `emit_usage_limits_updated`. Open questions worth settling before building: whether the pending state should also fire a Telegram ping (the user may be away from the machine entirely, which is exactly when a pending request matters most), and how it composes with the existing usage badge and context-alert border, which already own the icon.
